# 砍价侠 KanjiaX

> 现有工具给数据，砍价侠给决策。

一个面向消费者的 AI 购物决策引擎。输入商品关键词或链接，输出一句话决策——**买 / 等 / 换**，且每条结论附带可验证的证据链。

真实数据走**淘宝联盟 / 京东联盟官方 API**，不采用爬虫。仅依赖 Python 标准库，无第三方包。

```bash
git clone https://github.com/jiaojiaosr4/kanjiax.git
cd kanjiax
python main.py
```

## 四种运行模式

| 命令 | 数据源 | 是否需要凭证 |
|---|---|---|
| `python main.py` | 内置示例数据（离线演示） | 不需要 |
| `python main.py --tbk "耳机"` | 淘宝联盟物料搜索（升级版接口） | 需要淘宝凭证 |
| `python main.py --item "商品ID或链接"` | 淘宝商品详情（升级版接口） | 需要淘宝凭证 |
| `python main.py --jd [频道号]` | 京东京粉精选真实商品 | 需要京东凭证 |

`--jd` 频道号可省略，默认 1，试 `--jd 2` 可换频道。各模式在当前目录生成 `report.html`，页首显示查询对象、来源和生成时间。查询失败会写入失败报告并以非零状态退出。

> **关于示例数据**：仅用于离线演示决策引擎的逻辑，不代表真实商品结果。要看真实数据请用 `--tbk` / `--item` / `--jd`，页面顶部会标明本次数据来源。

## 课堂演示页

根目录 `index.html` 是一份**单文件静态快照**：logo、商品图全部内联，断网也能打开，双击即用。

- 数据来自淘宝联盟官方 API 的真实商品快照（蓝牙耳机 / 保温杯 / 电动牙刷等 24 个商品）
- 价格、到手价、佣金、销量和主图来自该次接口查询
- **放映时不调用任何 API**：这是刻意的安全边界，避免现场网络 / 限流 / 密钥风险；答辩时另跑上面的 Python 模式证明真实接口可调通
- 历史价格、评论去水、拼多多比价暂未接入，页面上如实标注「待接入」

想直接分享给朋友看界面：在仓库 **Settings → Pages → Build and deployment** 选 `main` 分支 / `root` 目录并保存，稍等片刻即可用 `https://jiaojiaosr4.github.io/kanjiax/` 访问（不带任何第三方域名）。

## 配置联盟 API

复制 `config.example.json` 为 `config.json`，按下面两段填写。**每人用自己的凭证**。

### 淘宝联盟（tbk）

1. 注册阿里妈妈（pub.alimama.com）并实名认证
2. 媒体备案，类型选「导购媒体」（公众号 / 小红书均可）
3. 创建应用，获取 `AppKey` 与 `AppSecret`
4. 获取推广位 PID（格式 `mm_账号_媒体_推广位`），取末段数字作为 `adzone_id`
5. 物料搜索需申请权限包 **27939**「淘宝客【推广者】商品物料获取」，审核通过后可用

### 京东联盟（jd）

1. 注册京东联盟开放平台（union.jd.com/openplatform）
2. 创建「导购媒体（社交媒体推广）」资质，等待审核通过
3. 取得 `appkey` / `secretkey`
4. 创建推广位，取得 `unionId` / `siteId` / `positionId`（三者拼接即 PID）

**京东权限边界（实测，非推测）**：

| 接口 | 状态 |
|---|---|
| `jd.union.open.goods.jingfen.query` 京粉精选 | ✅ 可用，本适配器主通道（基础权限包内） |
| `jd.union.open.goods.promotiongoodsinfo.query` 按 SKU 查详情 | 403，需网站 / APP 或更高等级 |
| `jd.union.open.goods.query` 关键词搜索 | 403，需 V2 等级（月 3 万单 / 3 万 UV，个人拿不到） |
| `jd.union.open.promotion.common.get` 通用转链 | 2001701，导购媒体 siteId 不支持 |

因此京东模式是「**按频道拉取真实商品 → 划算分排序 → 买 / 等 / 换 + 证据链**」，不是关键词搜索。用到的真实字段：标价 / 券后价 / 佣金率 / 30 天订单 / 评论数 / 好评率 / 券面额 / 店铺评分 / 破价标签 / 主图。

### 也可以走环境变量

环境变量中的必填凭证齐全时优先使用环境变量，否则读取 `config.json`。淘宝的搜索和单品查询使用同一套配置。

```bash
export TBK_APP_KEY="..." TBK_APP_SECRET="..." TBK_ADZONE_ID="..."
export JD_APP_KEY="..." JD_APP_SECRET="..." JD_UNION_ID="..." JD_SITE_ID="..." JD_POSITION_ID="..."
```

## 决策引擎

联盟商品缺少可用的标价或到手价时，报告标注价格未知，暂停折扣判断和排序。京东的换款建议要求存在同末级类目、不同商品 ID 且到手价更低的候选，具体型号和规格仍需核对。

### 评论去水（可解释规则）

检测两类刷单信号，规则全部可解释：

1. **模板话术检测**：好评同时包含「物流」+「质量 / 不错 / 好 / 满意」类高频词
2. **时间集中检测**：至少三条模板好评出现在同一组三个连续自然日内

同时提取 1–2 星评论中提及的质量关键词。示例模式同时满足集中评论占比至少 25% 和低星评论命中关键词时，会给出「换」建议。

### 历史价格判断

以「距近 30 天最低点的距离」判断当前位置：

- 当前价 ≥ 最低价 × 1.10 → 高位（建议等）
- 当前价 ≤ 最低价 × 1.05 → 低位（可入手）
- 否则 → 均值区间

### 决策优先级

1. 疑似模板评论比例和低星评论关键词同时触发规则 → **换**
2. 当前价处于高位 → **等**
3. 当前价处于低位且评论正常 → **买**
4. 默认 → **买**

### 划算度评分

课堂页和 Python 淘宝搜索使用相同的规则。划算分为折扣百分比 × 60% 加销量归一化得分 × 40%。淘宝按日销 50 件、京东按近 30 天 1,500 单封顶。佣金率仅展示。

### 记录真实历史价

```bash
python main.py --item "商品ID或链接" --track-price
```

指定 `--track-price` 后，可将同一淘宝商品每天最后一次查到的到手价、标价和促销信息存入本地 `price_history.sqlite3`。用同一商品、同一规格定期运行，报告会画出最近 30 个自然日内实际记录的点。至少记录 3 天后，当前到手价达到已记录最低价的 110% 时会提示观望。联盟到手价可能受规格和优惠条件影响。

## 项目结构

```
kanjiax/
├── engine.py              # 决策引擎：比价 + 历史价 + 评论去水 + 决策 + 排序

├── data.py                # 内置示例商品数据
├── main.py                # 入口：四种运行模式 + 报告渲染
├── config.example.json    # 联盟 API 配置模板（淘宝 + 京东）
├── demo_products.md       # 课堂演示用真实商品链接清单
├── index.html             # 课堂演示页（单文件静态快照，双击即开）
├── price_history.py       # 淘宝单品到手价的 SQLite 记录
├── tests/                 # 离线回归测试
├── README.md
└── LICENSE
```

## 团队协作流程

推荐工具：**GitHub Desktop + VS Code**，仓库 `main` 分支为主干。

| 步骤 | 做法 |
|---|---|
| ① 同步最新版 | GitHub Desktop 切到 `main` → `Fetch origin` → 若出现 `Pull origin` 再点一下 |
| ② 为任务建分支 | 从最新 `main` 点 `Current Branch → New Branch`，如 `feature/jd-report`、`docs/readme` |
| ③ 修改并上传 | VS Code 改文件 → GitHub Desktop 填写提交说明 → `Commit` → 首次 `Publish branch`，之后 `Push origin` |
| ④ 请人检查并合并 | GitHub 发起 Pull Request（目标选 `main`）→ 请一位队友试跑 / 审阅 → 通过后 `Merge pull request` |

规则：

- 不要在 `main` 上直接改；按任务建分支，谁改了什么在提交记录里一目了然
- 两个人改同一文件的不同位置，Git 通常能自动合并；改到同一行需一起确认最终写法
- 第一次协作可让每人新建一个自己的 `.md` 文件，完整走一遍「提交 → 审核 → 合并」
- 几个人实时共同写同一份 Word / PPT 时，用腾讯文档、飞书或 Microsoft 365 更顺手；源码和 Markdown 说明继续放 GitHub

## 关于爬虫

本项目不采用爬虫作为数据源。原因：国内电商对 headless 浏览器有强反爬（实测京东对 headless 返回首页而非商品页），爬虫脆弱且存在合规风险。走联盟官方 API 是合规、稳定的路径，顺便打通返佣商业闭环。
